# V1.1 fixes

This build fixes two issues discovered during device testing:

1. Recent Time refresh
   - Dashboard and Pay Period screens now reload AsyncStorage whenever the
     screen regains focus.
   - A newly saved manual or clock entry appears immediately after returning.

2. Straight-time incorrectly appearing as overtime
   - Work dates now use the phone's LOCAL calendar date.
   - The old build used `new Date().toISOString().slice(0, 10)`, which is UTC.
     In US Central Time during daylight saving time, entries created after
     7:00 PM could be assigned to the next date. A Friday could therefore be
     saved as Saturday, causing all hours to be classified as weekend overtime.

Additional fix:
- Manual-entry preview now uses the saved hourly rate and overtime multiplier
  instead of a hard-coded $25/hour.

Recommended test:
- Enter a weekday 06:00–16:00 shift with a 30-minute break.
- Expected with current break behavior:
  Straight time: 8.00 hours
  Overtime: 1.50 hours
  Paid time: 9.50 hours

Testing data reset:
- V1.1 uses new AsyncStorage keys so incorrect test records from the earlier
  build do not carry forward.
- Re-enter test shifts after launching V1.1.
