# Version 2.3.0 — team notes and account creation

- Team Hours displays notes from saved entries, including multiline text.
- Adding, editing or clearing notes syncs on the existing account/device journal.
- Structured rate/pay fields remain excluded from cloud records. Notes are shared
  exactly as entered: do not put sensitive or pay information in them.
- Team Hours offers email/password account creation with password confirmation.
  Firebase signs in the new user; team access still requires administrator approval.
- No changes to pay calculations, saved cards, rollover, clock persistence, exports,
  typed/dropdown times, theme, OCR configuration or EAS/GitHub Pages setup.
- No new dependencies. Android versionCode is 7.

## Required Firebase steps

1. In Firebase Console, select `timepaytracker`. Under Authentication → Sign-in
   method, ensure Email/Password is enabled.
2. Under Firestore Database → Rules, replace the rules with the entire included
   `firestore.rules` file and click Publish. Old rules reject the new notes field.
3. Upgrade all web and Android/iOS clients to 2.3 before sharing notes. Older app
   readers reject records containing notes. This release reads old records without
   notes correctly. Existing local entry notes upload on the next successful sync;
   review/remove sensitive notes before signing in or enabling the new rules.
4. Each employee selects Team Hours → New here? Create an account. They enter an
   email, password and confirmation. No shared/team password is needed.
5. To approve the employee, copy their UID from Authentication → Users (or the
   app's Team account panel). Under Firestore Database → Data, navigate to
   `teams` → `company-team` → `members`. Add a document whose ID is that UID:
   - `displayName`: string, employee's name (1–100 characters)
   - `role`: string, `member`
   - `active`: boolean, `true` (not the string "true")
6. Employee taps Retry Sync and Refresh Team Hours. A new unapproved account
   cannot read or publish team records. Users cannot approve themselves or edit
   membership through the client. No in-app administrator approval UI is included.

Registration does not copy coworkers' data or restore private payroll from another
device. Existing local account separation and explicit legacy-data claiming remain.
Firebase rules/configuration were not deployed automatically. Test live signup with
your own test account, approve it, and confirm access using a second approved account.
The supplied emulator tests are separate from the unit tests and require Firebase
emulator tooling. OCR still requires its previously documented backend configuration.
